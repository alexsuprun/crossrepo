Add `xr project sync [<project>]`. It takes the project by name or branch, else the current project folder, else a project picker in a codebase folder (`missing-argument` when not interactive). Under the codebase lock, for each repo of the project in record order, it first checks with no change that the worktree folder exists, is on the project branch, has no merge in progress and no unmerged files, and that the repo has a default branch (config `default-branch`, else `origin/HEAD`). Then it runs `git fetch origin` and `git merge --autostash --no-edit refs/remotes/origin/<default-branch>`. A repo is `ok` (`up to date`, `fast-forwarded to origin/<b>` or `merged origin/<b>`), `conflict` (with `files`; with `stashKept: true` too when the uncommitted changes conflict with the merge and stay in `git stash list`, and the hint is to fix the files, then `git reset` and `git stash drop`), or `failed`. A conflict stays in git's conflict state; `xr` never switches branches or commits by itself. Any `failed` or `conflict` repo fails the run with `repos-failed`, and the `repos` JSON items can now have `files` and `stashKept`. Ctrl-C stops a fetch at once but never a merge. It runs no `xr` hook; git's own hooks run as usual. The default-branch rule is now one shared service for `project create`, `project repo add` and `project sync`.
