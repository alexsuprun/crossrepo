Add `xr project remove [<project>] [--force] [--delete-branch]`. It finds the project by folder name or branch, or opens a picker of the projects with their branches; it never takes the current project without a name or a pick. A check phase changes nothing: a folder in the project folder that is not a repo of the project fails with `project-drift` (folders whose name starts with `.`, such as `.idea`, do not count and are deleted with the project), and changed, staged or untracked files in a worktree fail with `uncommitted-changes` (unpushed commits, stashes and ignored files do not count; `--force` skips only this check). Then the `pre-remove` hook runs; a failure gives `hook-failed` and the project stays whole. The delete phase removes the worktrees, then with `--delete-branch` each branch with `git branch -d` (an unmerged branch is kept with the warning `branch-not-merged`, exit 0), then the project folder. A missing worktree folder is pruned. A failure or Ctrl-C there lists the leftovers with cleanup commands. When `xr` runs in the project folder, it moves to the codebase first and the Report ends with a note to `cd` there. New error codes `uncommitted-changes` and `project-drift` (exit 1), and the warning code `branch-not-merged`.
