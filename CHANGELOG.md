# crossrepo

## 0.1.0

### Minor Changes

- [#53](https://github.com/alexsuprun/crossrepo/pull/53) [`020774a`](https://github.com/alexsuprun/crossrepo/commit/020774a509c84961ac6560d6687fe5d825827976) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr codebase clone`, which clones each repo of the codebase config that is not on disk yet, one at a time in config order, under the codebase lock. It uses the merged config, so a `remote` in `config.local.yaml` wins, and runs a plain `git clone`. A repo already on disk is skipped; a folder with no `.git` or a repo with no remote fails with a hint and is never touched. There is no undo across repos. New error code `repos-failed` (exit 1) when any repo fails. The `repos` list in JSON, next to `error` on a failure, has one `{ repo, status, message?, hint? }` item per repo; the new `hint` field says what to do for that repo. Ctrl-C stops the running clone, deletes its partial folder, marks it and the repos not reached as `skipped` with `interrupted`, and exits 130.

- [#46](https://github.com/alexsuprun/crossrepo/pull/46) [`35291d6`](https://github.com/alexsuprun/crossrepo/commit/35291d65306a7fe49e0b64d1976fc4d7d0507f97) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr codebase init`, which makes a folder of sibling git repos into a codebase. It records the `origin` remote and the default branch of each repo in `.crossrepo/config.yaml` and writes the `## Codebase` section of `AGENTS.md`. If a step fails, the done steps are undone.

- [#54](https://github.com/alexsuprun/crossrepo/pull/54) [`e045a6b`](https://github.com/alexsuprun/crossrepo/commit/e045a6b3117e54ac80d857dcb761a89fff5cb0df) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr codebase pull`, which runs `git pull --ff-only --no-rebase` in each repo of the codebase config that is on disk, one at a time in config order, under the codebase lock. It pulls the checked-out branch from its own upstream, never switches branches, never rebases and never makes a merge commit. A missing repo is skipped with a hint to run `xr codebase clone`; a folder with no `.git` fails and is not touched. A repo that cannot be fast-forwarded, has no upstream, has a detached HEAD or has local changes in the way fails with git's message and a hint for the next step. There is no undo across repos. Any failed repo ends the command with `repos-failed` (exit 1). Ctrl-C stops the running pull, marks it and the repos not reached as `skipped` with `interrupted`, and exits 130.

- [#49](https://github.com/alexsuprun/crossrepo/pull/49) [`0caad61`](https://github.com/alexsuprun/crossrepo/commit/0caad61b4acdb54c99dff0c9046b1ac6c010beb4) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr codebase repo add <url> [name]`, which clones a repo into the codebase, and `xr codebase repo add <folder>`, which adds a repo folder that is already directly in the codebase. Both add the repo at the end of `repos:` in the codebase config, keeping its comments and key order, and update the `## Codebase` section of `AGENTS.md`. The command takes the codebase lock; if a step fails or you press Ctrl-C, the done steps are undone and a folder that this run cloned is deleted. New error codes: `repo-exists` and `not-in-codebase`.

- [#48](https://github.com/alexsuprun/crossrepo/pull/48) [`574921e`](https://github.com/alexsuprun/crossrepo/commit/574921ebc20c89412dc48ce7e453a3b60a48b06e) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr codebase repo list`, which prints each repo of the codebase with its remote, default branch and description, and whether its folder has a `.git`. It uses the merged config, so a `remote` in `config.local.yaml` wins. It works in a codebase or a project, changes nothing and takes no lock.

- [#50](https://github.com/alexsuprun/crossrepo/pull/50) [`1a4afe6`](https://github.com/alexsuprun/crossrepo/commit/1a4afe6d923f31af7f18c6ea29dfbf3616e1feb3) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr codebase repo remove <name>`, which removes a repo from the codebase config and the `## Codebase` section of `AGENTS.md`, and deletes its folder. It first checks, under the codebase lock, that no project of the codebase uses the repo and that the folder has no uncommitted changes, unpushed commits or stashes; when a check fails, nothing changes. `--keep-folder` keeps the folder, and `--force` deletes it without the work check. A failed or stopped delete lists what is left with the commands to finish by hand. New error codes: `repo-not-found`, `repo-in-use`, `invalid-project-record` and `would-lose-work`. In JSON, `error.details` now also carries the plain data of an error, and a `value` field can be a boolean or a number.

- [#42](https://github.com/alexsuprun/crossrepo/pull/42) [`b508db3`](https://github.com/alexsuprun/crossrepo/commit/b508db3fe2dc84f7d4db28fd9c3ac472f1926d3c) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr config show`, which prints the merged config and the file that gives each value. `projects-dir` now defaults to `.projects`. Unknown config keys give a warning with a "did you mean" hint.

- [#57](https://github.com/alexsuprun/crossrepo/pull/57) [`b118fc7`](https://github.com/alexsuprun/crossrepo/commit/b118fc7dc191b3211c83357527a0f3e70a09ab1b) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add interactive pickers to `xr codebase repo add` and `xr codebase repo remove`. With no argument, in a terminal, `repo add` lets you pick a repo folder of the codebase that is not in the config yet, and `repo remove` lets you pick a repo of the codebase config; the picker shows on stderr, and Ctrl-C or Escape stops the command with `interrupted` (exit 130) and changes nothing. With no terminal, `--json` or `--no-interactive`, or when there is nothing to pick, a missing argument now fails with the new code `missing-argument` (exit 2) instead of `usage`; the message lists the choices, and `error.details` is `{ argument, choices }`.

- [#47](https://github.com/alexsuprun/crossrepo/pull/47) [`7fa2fad`](https://github.com/alexsuprun/crossrepo/commit/7fa2fad91887f6dd23ec3911a46b30e58fd72117) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add a codebase lock and Ctrl-C undo. A command that changes files takes the lock `.crossrepo/xr.lock`, so a second such command in the same codebase fails at once with `lock-held`; a lock left by a process that is not running is taken over with a `stale-lock` warning. Ctrl-C during `xr codebase init` undoes the steps that are done and exits with code 130 and the `interrupted` error.

- [#40](https://github.com/alexsuprun/crossrepo/pull/40) [`0d41226`](https://github.com/alexsuprun/crossrepo/commit/0d41226a13ee7c4a2b356b5463388b7c9ff30054) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add one output shape for every result and error: readable text in a terminal, or one JSON object on stdout with `--json`, including for `--help` and `--version`. Add the `--verbose` flag, which prints the stack trace of an internal error.

- [#66](https://github.com/alexsuprun/crossrepo/pull/66) [`3ed6d37`](https://github.com/alexsuprun/crossrepo/commit/3ed6d3797ce13d99362cae570ca0d32f631990ef) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr project create <branch> [<repo>...|--all]`, which makes one project folder with a git worktree of each chosen repo on the branch, writes `.crossrepo/project.yaml` and the project `AGENTS.md`, then runs each `post-create` line with `sh -c`. With no repos, a multi-select picker opens in a terminal. It checks everything first under the codebase lock; any later failure or Ctrl-C undoes all steps, and never deletes a branch that existed before. `project.vars` values can now be numbers and booleans, passed to hooks as text. New error codes: `project-exists`, `branch-in-use`, `no-default-branch`, `hook-failed` and `sh-not-found`.

- [#67](https://github.com/alexsuprun/crossrepo/pull/67) [`54f23aa`](https://github.com/alexsuprun/crossrepo/commit/54f23aafcadd106677c0ff42f4aa764a841093f2) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr project list` and `xr project info [<project>]`. `list` prints each project of the codebase in name order, with its branch, created date and repos; `info` prints one project, found by folder name or branch, with its path, codebase, created time and whether each worktree folder exists. In a project folder, `info` with no argument shows that project; in a codebase folder it fails with `missing-argument` and lists the projects, with no picker. Both read only: no lock and no git command. A project record that is not valid is a warning `invalid-project-record` there, and the other projects still show. New error code `project-not-found` (exit 1).

- [#68](https://github.com/alexsuprun/crossrepo/pull/68) [`ca6c82b`](https://github.com/alexsuprun/crossrepo/commit/ca6c82b5178086a1e7f8e5a8a2a1a542c498de98) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr project remove [<project>] [--force] [--delete-branch]`. It finds the project by folder name or branch, or opens a picker of the projects with their branches; it never takes the current project without a name or a pick. A check phase changes nothing: a folder in the project folder that is not a repo of the project fails with `project-drift` (folders whose name starts with `.`, such as `.idea`, do not count and are deleted with the project), and changed, staged or untracked files in a worktree fail with `uncommitted-changes` (unpushed commits, stashes and ignored files do not count; `--force` skips only this check). Then the `pre-remove` hook runs; a failure gives `hook-failed` and the project stays whole. The delete phase removes the worktrees, then with `--delete-branch` each branch with `git branch -d` (an unmerged branch is kept with the warning `branch-not-merged`, exit 0), then the project folder. A missing worktree folder is pruned. A failure or Ctrl-C there lists the leftovers with cleanup commands. When `xr` runs in the project folder, it moves to the codebase first and the Report ends with a note to `cd` there. New error codes `uncommitted-changes` and `project-drift` (exit 1), and the warning code `branch-not-merged`.

- [#71](https://github.com/alexsuprun/crossrepo/pull/71) [`e8f4c33`](https://github.com/alexsuprun/crossrepo/commit/e8f4c33fd953e2f49bf51f8dae522a3cde555742) Thanks [@alexsuprun](https://github.com/alexsuprun)! - Add `xr project repo add [<repo>...]`, `xr project repo remove [<repo>...] [--force] [--delete-branch]` and `xr project repo list`. Each takes `--project <project>` (folder name or branch), else uses the current project folder, else opens a project picker in a codebase folder (`missing-argument` when not interactive). `add` checks each repo first (known, on disk, not in the project, nothing at its worktree path, fetch, default branch, branch not in use), then adds the worktrees on the project branch and writes the record and the `## Codebase` and `## Repos` sections of `AGENTS.md`; any failure or Ctrl-C undoes every step. `remove` checks that each repo is in the project, that one repo stays, and that no worktree has uncommitted changes (`--force` skips only this), then removes the worktrees, with `--delete-branch` each merged branch, and only then writes the record and `AGENTS.md`. Neither runs a hook. `list` prints each repo with `✓` or `–` and its description, with no git call and no lock; JSON has `project` and `entries`. New error codes `repo-already-in-project` and `last-repo` (exit 1).

### Patch Changes

- [#58](https://github.com/alexsuprun/crossrepo/pull/58) [`2eb5919`](https://github.com/alexsuprun/crossrepo/commit/2eb5919d3c2ecda01d02b76cea8e75f32e4fdc0e) Thanks [@alexsuprun](https://github.com/alexsuprun)! - `xr codebase clone` and `xr codebase pull` no longer print each repo line twice. When stdout and stderr are both the terminal, the final result leaves out the per-repo lines that stderr already showed. On a failure, stderr no longer repeats the lines before the error. A piped stdout and `--json` still get the full list.

- [#52](https://github.com/alexsuprun/crossrepo/pull/52) [`4760c0d`](https://github.com/alexsuprun/crossrepo/commit/4760c0dc099e27e131e99b70e12ff78734c99cf6) Thanks [@alexsuprun](https://github.com/alexsuprun)! - A folder delete now checks that the folder is gone and tries again up to 3 times. Before, `xr codebase repo remove` could report the folder as deleted while part of `.git` was still there. If the folder still exists after 3 tries, the delete fails and the folder is listed as left over.
